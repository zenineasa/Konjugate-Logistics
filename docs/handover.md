# Handover

For whoever picks the toolbox up next, person or agent. Read [direction.md](direction.md) first: it says where the toolbox is going and why. This file says how to work in it, what state it is in, and what is easy to get wrong. Last updated October 2026, after milestones A and B and most of C (storage, stock at stores, vehicle types, product categories, suppliers that make to order).

## Where things stand

- **Working today:** the map-first workflow (milestones A and B, [mapFirst.md](mapFirst.md)): the roads of a city or region loaded alone, a network placed on them from a palette of roles (supplier, port, warehouse, store, dark store, customer area) with a card per site, links suggested then edited by dragging, routing in the window fast enough to follow a dragged site, suggestions from public data (ports with IMF PortWatch, warehouses, towns) only when asked for, a CSV in and out and a model built from the sites and links. Behind it, the port-to-hinterland planner it grew from: a model built over the real roads and four scenarios forked from the baseline (chokepoint with cargo lost, delayed or diverted to one or two ports; road closure; fleet change; demand change, including demand while a cut lasts), with results on the map and in a summary in business terms (stock-out days, sales lost and their value, running costs), the latest run set beside an earlier one. Every input is labelled with where it came from. A showcase on Dubai during the 2026 Hormuz closure was built and filmed with it.
- **Part of C:** a network placed in the window counts pallets; warehouses, stores and dark stores have a storage capacity and a stock cover; a store or dark store holds stock (a stock room restocked by road, and its shoppers); every link to a warehouse or store runs on one or two vehicle types from a catalogue the user edits (heavy, medium and small trucks and mini-vans by default), with a fleet per lane the user sets or the toolbox sizes. The fleet operator is for the earlier region workflow only. The network carries product categories (ambient, chilled and frozen by default), each a copy of the network in the model with a site's mix, its vehicles and its room shared among them; a supplier makes what is ordered from it over a lead time, up to what it can make a day; chilled and frozen goods go by refrigerated vehicles only; results name the categories a store ran out of and give a table by category.
- **Decided next:** the rest of the general supply network ([direction.md](direction.md), milestones C to H): fleets based at sites and shared among their links and categories, calendars and shifts with a holiday calendar, a supplier late or short as a scenario, network what-ifs, dark stores with the last mile. A customer area is a demand zone with no stock.
- **Before building:** the practitioner questions at the end of that section are meant to be asked first. The direction came from one retail supply chain manager's reaction to the showcase video; more answers should shape milestone A.

## Setup

- A checkout of the public Konjugate repository beside this one (`../konjugate`), or `KONJUGATE_DIR` pointing at it (`scripts/konjugatePaths.mjs`). The engine tests need Konjugate's built engine (`out/engine/konjugateEngine` in that checkout), or, on a machine without one for its platform (a Linux VM beside a Mac build), `KONJUGATE_ENGINE=export`: each model then runs as Konjugate's code export writes it, a Python program that follows the engine step for step (Konjugate checks that in `codeExportFidelity`), with no validation beyond the model builder's equation checks. The window test takes the same setting to run a scenario. The interaction tests run Konjugate's Electron app from source.
- `npm test`: unit tests (fast). `npm run test:engine`: the engine CLI on generated models, checking conservation. `npm run test:interaction`: builds the packages and drives the real app with Playwright (several minutes; under heavy machine load a step can time out, so rerun once before suspecting a bug). `npm run build` writes the packages to `out/`; `npm run install:dev` installs them into a local Konjugate.
- `node scripts/liveRegionCheck.mjs --place "Rotterdam" --pick 2 --margin 10 [--run --scenarios]` fetches a real region exactly as the window would (`--margin` boxes the place's bounds as the window does), caches it, prints coverage, candidates and the model, and with `--run` runs it. The public Overpass server is fair-use and often overloaded: fetch one region at a time, never in parallel.

## Code map

- `packages/engine/components/*.json`: the component templates (Port, Road lane, Rail lane, Warehouse, Demand zone, and the shipment and delivery bundles), with their equations. Konjugate states are scalars and edges are bidirectional, which is how goods and trucks are conserved.
- `packages/toolbox/addon.json`: the add-on manifest: the importer, the scenarios (each declares the parameters it changes, as `supplied` interventions) and the Konjugate features it `requires`.
- `packages/toolbox/importers/region.mjs`: the importer Konjugate runs in a worker. The window's steps: `roads` (the map and the compacted road graph), `discover` with `sources` (the suggestions asked for), `sites` (a CSV) and `buildNetwork` (the model from pins and links). The earlier workflow's `discover` (no sources) and `build` stay for `liveRegionCheck.mjs` and the engine tests.
- `packages/toolbox/toolbox.mjs`: the window: state (`pins`, `links`, `suggestions`), the four steps (Map, Network, Model, Scenarios), `networkChanged` (suggest, route only what moved, redraw), the pin and link cards, suggestions on request, the session (version 2, with a migration from version 1), scenario settings, running a scenario (`scenarioRun`, `chokepointRun`), the summary (`summariseRun`, `scenarioHeadline`, `renderScenarioResult`), the runs kept to set side by side (`keepRun`, `renderComparison`) and the map's flows (`renderFlows`). `mapView.mjs` draws the map; `index.html` and `styles.css`.
- `packages/toolbox/lib/`: `discovery.mjs` (OpenStreetMap to candidates: ports, logistics zones, towns, coverage, notices), `portwatch.mjs` (IMF PortWatch fetch, matching ports, history, breaks), `network.mjs` (roles and their defaults, pins, suggested links, `networkProblems`, `networkSelection` for the importer), `vehicles.mjs` (the vehicle catalogue, a link's vehicles by its kind, what may deliver to stores, what carries chilled goods), `categories.mjs` (the category catalogue, a site's mix, a supplier's lead times), `builtView.mjs` (the built model by site and link: `siteView`, `mergeSeries`, and a scenario spread over a link's or a port's copies), `travelTimes.mjs` (the user's own times: reading, flags, calibration, the map links and the CSV), `routing.mjs` (the window's router: compacted graph, grid snapping, A*, nearest sources), `regionModel.mjs` (a model from the user's links, or by gravity for the earlier workflow: flows, lanes, fleets, provenance; still ports to zones to towns underneath, with a stock room and a store lane per store when the network has vehicle types: `placeStock` and `placeLane`; `buildScope` builds one network, `buildRegionModel` one for each category onto the same builder, after a draft that says what each category needs on each link and at each site, and `assemble` puts them together), `modelBuilder.mjs` (placing templates; `as` places a template's shared parameter as another, so a vehicle type is one parameter for every lane it runs on, and `unitNames` says pallets where the templates say TEU), `roadGraph.mjs` and `corridors.mjs` (routing, and lanes merged into corridors for the map), `scenarios.mjs` (the scenario plans: paths supplied per parameter; `supplierPlan` for a supplier short or late, `siteDownPlan` for a warehouse down or a store closed), `chokepoints.mjs`, `operator.mjs` (fleet operators), `geography.mjs` with `geography/` (Natural Earth tiles), `overpass.mjs`, `places.mjs`, `sites.mjs` (the user's CSV), `geo.mjs`, `mapData.mjs`.
- `scripts/`: `liveRegionCheck.mjs` (above), `templatePlacement.mjs` (the `ModelBuilder` the tests use outside Konjugate), `buildGeography.mjs`, `build.mjs`, `installDev.mjs`, signing scripts.
- `tests/`: `unit/` (node:test), `engine/` (runs the engine CLI and checks invariants; `harness.mjs` holds the checks and the code-export runner, `networkModel.mjs` runs a placed network, `vehicleNetwork.mjs` one with vehicle types and stores that hold stock, `categoryNetwork.mjs` one with three categories and suppliers that make to order), `window/` (the window in a plain browser with a stand-in host: `npm run test:window`, no Konjugate build needed), `interaction/` (the real app), `fixtures/syntheticRegion.mjs` (a made-up coast every test uses) and `fixtures/roadGrid.mjs` (an invented city grid and a seeded random generator).

## How a scenario runs

The window computes, for each parameter a scenario changes, a held path of values over time (`scenarios.mjs`), and calls `api.runScenario(id, { supplied: { byParameter }, forkAt, runTime, signals })`. Konjugate runs the baseline, forks it at `forkAt` and follows the supplied paths as stored schedules; the window summarises both branches. A parameter can only be scheduled if it is live and indexed (`built.parameterIndex`); a value outside its slider is held to the slider and reported back as `clamped`, which the window shows. Every parameter a scenario declares in `addon.json` must be supplied, with at least one entity, or the run is refused.

## Things that are easy to get wrong

- **Orders that cannot be delivered.** The warehouse orders up to a target counting what is on order. An order placed on a lane or port that cannot deliver (a closed road, cargo that will never come) counts as on its way and cuts the warehouse's orders on its other lanes while its stock runs out. Scale the order shares instead (`chokepointOrders`, `closurePlan` in `scenarios.mjs`). Any new disruption must respect this.
- **Conservation.** The engine tests check that containers, trucks and the on-order books are conserved in every run. Keep them passing; they caught real bugs.
- **One time step everywhere** (15 minutes, hourly outputs): edges between nodes with different substeps do not conserve exactly yet. So a lane's travel time is never less than six steps (an hour and a half) and its loading time never less than two, in a network with vehicle types: a city delivery of half an hour, in three Erlang stages, would make the explicit steps overshoot and the run blow up once disturbed (it held still in the baseline, which is why only a scenario showed it). The provenance says where a time was raised.
- **Storage capacity is a planning limit, not a wall.** A warehouse never orders towards more than its room, but what it has already ordered still arrives, so after a surge ends its stock can pass its capacity (Space used above 1; the summary marks it). Vehicles waiting at a full warehouse's gate would make it a wall; not built.
- **Names of stock rooms.** A store's stock is the node "<store> stock", its shoppers the node of the store's name; a lane's `to` is the stock room and its `site` the store. Results, scenarios and the summary rely on that.
- **Categories are copies.** With more than one category every node is named "<site>: <category>" (a stock room "<store> stock: <category>", a lane "Road A → B: <category>"), and `built.lanes`, `ports`, `towns` and `stores` hold one entry for each copy, with `link`, `site`, `fromSite` and `category` saying what it is a copy of. The window never reads those lists directly: `view()` in `toolbox.mjs` (`siteView`) adds them up by site and link, `mergeSeries` does the same to a run, and a scenario's paths go to the copies (`lane.members`, `closureAcross`, `affectedAcross`, `diversionAcross`). Anything new that lists, draws or summarises goes through the view; anything new that supplies a path names the copies. One category alone is built with no suffix, node for node as a network with none.
- **On Konjugate's canvas.** A model is laid out north up over about 80 units, and with categories each copy has a place of its own (`categoryShifts` in `regionModel.mjs`: the grid with the shortest diagonal, since Konjugate fits a model to the window by its size and draws names at one size, so a long row of copies is shown small under a pile of names). Until the release after Konjugate 1.1.9 the canvas's fog had one density, and a model this wide showed its names and none of its shapes or relationships; `fogDensityFor` in Konjugate's `src/renderer/viewportLayout.mjs` thins it with the camera's distance. Spreading a model wider does not keep names apart: after the fit, only how the sites lie relative to each other does.
- **Shelf life is an excess over expected sales, not an age.** The Warehouse template wastes what a site holds beyond `forecast x shelfDays`, over a day, into `spoiled`; with stock for less than the shelf life nothing is wasted, as when the oldest goods go out first. So a site's order rule must not aim past the shelf life: `placeStock` holds the cover to it and gives the site its own `coverDays` (capping only the starting stock left the baseline drifting, the order rule still aiming at the shared cover). The forecast is of demand, not of sales, so a closed store wastes nothing; and goods do not carry their age from a warehouse to a store. The conservation check counts `spoiled`.
- **Links between warehouses.** `links.transfer` in the builder: a standing link's share of what its destination sends out is added to what its origin sends out, downstream first (a circle is refused), and what a warehouse needs from suppliers and ports (`sourceNeed`) is its throughput (`zoneDemand`) less what warehouses send it; only `sourcedZones` take part in the balance with the sources. A lane between warehouses is kind 'transfer': a Store shipment (the orders reach the origin's forecast), with a supply lane's gate hours and vehicles. A backup is the same lane on standby (no flow, no vehicles). When a plan moves orders elsewhere (`takers` in `scenarios.mjs`), a site's backup lanes take them first, evenly, and `fleetsFor` hires their vehicles; with none, its other lanes take them by what they carry. That is why the road closure, supplier and site-down scenarios all declare `fleetSize`, and name a lane at the fleet it has when nothing is hired.
- **A supplier makes to order.** Its lane's `requested` holds what the supplier still has to make or has ready (not half a day of orders, as a port's lane does), the warehouse's planned replenishment time includes the lead time, and each lane draws on its `supplyShare` of the supplier's ready goods. A supplier's `Supplies` figure is what is ordered from it in the baseline, and the stores' figures are still scaled to match the sources, category by category.
- **Vehicles and room are shared when built, not as the model runs.** A link's vehicles of a type are counted once, in whole vehicles, and split among its categories by need, so a category's count is a fraction; `fleetPlan` scales a fraction as it is. A lane releases only idle vehicles, so cutting a fleet that is mostly idle (one truck where a tenth would do) changes little.
- **Python 3.9 and the export.** Python 3.9 (macOS's own) refuses a source line of several thousand bytes with a non-ASCII character in it ("Non-UTF-8 code"), and the exported program's header names every state on one line, with Konjugate's dash in every name. Konjugate's `codeExport.mjs` writes that line in ASCII escapes from the release after 1.1.9; with an earlier checkout, `PYTHON=/opt/homebrew/bin/python3 KONJUGATE_ENGINE=export npm run test:window` runs it on a later Python. The window test says why a run was refused instead of waiting two minutes for it.
- **A supplier short is cut from its orders, late in all it is making.** `supplierPlan` holds a short supplier's capacity at its share of what is ordered from it in the baseline (a cut of its capacity would vanish in its headroom), and a late one's lead time longer, which slows what is already in production and lets it out in a burst when the lead time is its own again. In 'wait' mode the warehouses' order shares are held as they are: the orders are late, not lost, so they are not scaled away as a closed road's are. A scenario that names a parameter must supply it for at least one entity, so the plan always holds all three (capacity, lead time, order shares).
- **A site down is its lanes and its deliveries.** `siteDownPlan` closes every lane into and out of the site's stock nodes, holds the order shares over them at nothing (the closure rule: an order on a closed lane counts as on its way), and sets the `share` of every delivery from them to nothing, which is why every delivery's `share` is live and `built.deliveries` lists them. A closed store's sales are lost by the Delivery bundle's own rule (its `lostShare` of what its stock cannot meet), so nothing new was needed in the templates. A warehouse with no delivery of its own still supplies `share`, for one delivery at its usual value, because a scenario must supply every parameter it declares.
- **The ranking runs the window's own scenarios.** `rankFailures` in `toolbox.mjs` makes each failure the scenario its tab would (`failureRun`), runs it through `api.runScenario` with `retain: false` (the host keeps the baseline between runs and lets each fork go), summarises it with `summariseRun` and keeps a few figures. It adds nothing to the model or the manifest, so a new kind of failure is a new entry in `failuresToRank` and `failureRun`.
- **Travel times of the user's own** (`lib/travelTimes.mjs`) are door to door: in the model they replace the routed time plus the gate hours, and no vehicle's top speed is applied. A link carries them as `link.time`, sent as `leg.own`; the calibration goes as `settings.timeFactor`. Changing a link's time or vehicles makes it the user's, and with it every link into the same site, as drawing a link does, so the site's other suggested links are not suggested away. The maps open through Konjugate's `openLink` (`links.open`, only the hosts in the manifest's `links.hosts`); the window never fetches from them.
- **Store lanes and supply lanes.** `built.lanes` holds both, told apart by `kind` ('supply' or 'store'); only supply lanes are drawn as corridors, and warehouses are the ends of supply lanes.
- **Build time.** The window routes the network itself (`routing.mjs`) and the importer trusts its legs, so a build no longer routes; the earlier workflow's build still does, and a Dubai build with standby lanes passed 30 seconds under load. Konjugate gives an importer 120 seconds.
- **The host's limits.** An importer may return 8 MB to the window (the roads step refuses an area whose roads would be more), a window may send 2 MB of options (a build leaves the supply links' roads out beyond that, and the lanes are drawn straight) and keep a 2 MB session (links are saved without their legs and routed again on reopening). `tests/window/host.mjs` applies the same limits.
- **Suggested supply links and balance.** A source ships a fixed amount; with too few links it may have nowhere to send it, and the build fails. That is why a small network suggests every source to every warehouse. Links the user draws are built as drawn, so a user can still draw a network that cannot balance; the error says so.
- **The window's Run after a change.** With "Keep the canvas in step" on, a rebuild can be under way when Run needs its own build; Run waits for it (fixed). Keep that in mind when adding steps that build.
- **Caches live in `out/`,** which is git-ignored and cleared by a clean. Region caches (`out/regionCache/`) must be fetched again after one.
- **Two caches of map data.** The app's: Konjugate keeps what the window fetches (with `cache: 'use'`) in `<userData>/addonCache/konjugate.logistics.toolbox/`, up to 512 MB, 30 days, kept across reinstalls, removed with the add-on, cleared from the Map step; the window never sees the files (`src/addonCache.mjs` in Konjugate). The live region check's: `out/regionCache/`, for the scripts only.
- **Region boxes.** A city's search result can stop short of its port (Rotterdam); the window warns when a busy PortWatch port lies just outside. Town populations in OpenStreetMap can be a district's (set aside above 250,000 for a town).
- **Lost sales are a share of the shortfall, not of the queue.** The Delivery bundle drops from a zone's backlog into its `lost` total `lostShare` of the demand its warehouse's stock cannot meet (its share of the stock per draw-down time short of its share of demand), so shoppers are lost while the shelves are short and not afterwards, while the waiting ones are served. 0 (the bundle's default, every town and customer area) keeps the old behaviour. Backlog = start + ordered − delivered − lost; the engine harness checks it.

## Known open items

- Two ports splitting a diversion deliver 1.7 points less than one port taking it all, with the same cargo carried: not traced.
- Demand changes only by the figure the user gives; roads never congest; goods arriving overland from outside the region are not modelled.
- The interaction test's reopen step (session restored after closing the window) can time out under heavy load.
- Categories: a category's idle vehicles on a link do not carry another's goods, and its share of a site's room does not hold another's; a category has no stock cover of its own; the sites CSV names categories, so a file made for one network's categories says which it lacks when loaded into another.
- A supplier asked for more than it can make (orders moved to it when another road closes) delivers late, and the warehouse counts those orders as on their way meanwhile.
- A fleet operator's file is not yet read into the vehicle catalogue (its truck sizes as types, its contracts as fleets on links).
- City streets for a large city may come close to what the window may receive; not yet tried on real data.

## How the owner works

- **Builds on GitHub only for a version.** `release.yml` builds, signs and publishes on a `v*` tag; `build.yml` (unsigned, with the unit tests) runs only when started by hand from Actions. Nothing builds on an ordinary push, in this repo, Konjugate core or the other add-ons. Run `npm test` before tagging.
- **Release Konjugate before the toolbox when the toolbox needs something new from it.** The add-on's `requires` in `packages/toolbox/addon.json` names the Konjugate features it uses; a Konjugate without one will not run it. Today it needs Konjugate 1.1.9 or later (`fetchCache`, `keepSession` and `openLink` came in 1.1.9).
- **The owner commits.** Propose a commit message: one sentence on the change in behaviour, in the style of `git log`, no prefixes.
- **Prose** (docs, UI text, comments): plain words, no em dashes, no Oxford commas.
- **Honesty is a feature.** Every input says whether it is sourced, routed, assumed, synthetic or the user's; results compare choices and are never presented as forecasts; scenarios are never tuned to look better; limits and bugs are stated plainly.
- **Every fix gets a test** that would have caught it. Keep `ReadMe.md` and `docs/direction.md` current as things change.
- **Every user, every action.** Newcomers, regular users and power users each get a full way to do everything: a button or menu, a gesture, a key ([interaction.md](interaction.md)). A keyboard shortcut is never the only way, and every change can be undone.
